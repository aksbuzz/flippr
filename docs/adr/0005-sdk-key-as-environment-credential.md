# 0005. SDK key is the environment credential and the Redis key namespace

- **Status:** Accepted (retrospective)
- **Date:** 2026-10-07

## Context

The evaluation service must identify which environment a request is for, authorise it, and find the
right value with a single Redis lookup and no database access
([0002](0002-control-plane-data-plane-split.md)).

## Decision

- Each environment has one `sdk_key`, generated by the management service when the environment is
  created: `{environmentName}_sdk_key_{projectId}_{32 hex chars from crypto.randomBytes(16)}`.
  It is stored in plaintext in `environments.sdk_key`.
- Clients send it as the raw `Authorization` header value (no `Bearer ` prefix) to
  `GET /api/v1/evaluate/flags/{flagKey}` on the evaluation service.
- The Redis key is `flag:{sdk_key}:{flag_key}`. The value is the JSON encoding of the final value
  (`true`, `100`, `"Buy Now"`, `{...}`), which the evaluation service decodes and returns as
  `{"value": <decoded>}`.
- A missing key returns `200 {"value": null}`. A missing `Authorization` header returns 401.
  There is no distinction between an unknown SDK key, an unknown flag, and an unseeded flag.

## Alternatives considered

- **Hash the key at rest and in Redis:** better if Redis or a DB dump leaks, at the cost of an
  extra hash per request (cheap) and a one-time reveal of the key.
- **Separate server-side and client-side keys:** the usual industry split, so that browser code
  cannot read every flag. Not done here.
- **Bearer tokens and a lookup table `sdk_key -> environment_id`:** more flexible rotation, but an
  extra Redis read.

## Consequences

**Positive**

- One Redis `GET` per evaluation with no parsing of project or environment. Keys are unguessable
  (128 bits of randomness).

**Negative / risks**

- The key is the only credential and also appears in clear text in Redis keys, in the
  `GET .../environments` API response (now behind the admin token, and masked in the UI), and in
  `rest.http`.
- No rotation, revocation, or expiry. Compromise means deleting and recreating the environment,
  which the API does not support yet.
- One key type means it is unsafe to put in browser code. The evaluation service can now answer
  browser calls (`CORS_ALLOWED_ORIGINS`, off by default, see [0009](0009-evaluation-service-in-go.md)),
  but a browser-held key can still read every flag value of that environment.
- The environment name is embedded in the key. It is now validated (letters, digits, space, `.`,
  `_`, `-`, at most 50 characters) and spaces become `-`, so the key stays within `VARCHAR(255)` and
  free of separators. `environments.sdk_key` is also `UNIQUE`.
- The key/value format is an unversioned contract between two services in different languages. It is
  now covered end to end by `scripts/smoke.mjs`.
